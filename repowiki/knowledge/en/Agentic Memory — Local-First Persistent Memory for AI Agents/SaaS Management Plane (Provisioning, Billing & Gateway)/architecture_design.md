Two-file Python package with an explicit boundary: `store.py` owns the SQLite-backed `CloudStateStore` (customers, deployments, subscriptions, invoices, plans, usage) plus a numbered-migration runner (`run_cloud_migrations`) that applies `migrations/*.sql` up/down scripts against `cloud_state.db`, tracking schema via `PRAGMA user_version`. `gateway.py` exposes `GatewayRouter`, which resolves a `deployment_id` through the store, enforces active/inactive and plan-limit checks (daily calls, storage MB, seats), increments usage counters, then transparently forwards the request to the deployment's `api_base` using stdlib `urllib.request` and returns a uniform `{status, headers, body}` envelope. The package docstring and code enforce the hard rule that this DB never stores memories/audit logs — cross-deployment reads (seat count, audit-log sync) are done by opening the per-deployment `memory.db` read-only via `file:...?mode=ro` URIs. Dependency direction is one-way: `gateway → store`; migrations live under `infra_cloud/migrations/` as plain SQL files.
