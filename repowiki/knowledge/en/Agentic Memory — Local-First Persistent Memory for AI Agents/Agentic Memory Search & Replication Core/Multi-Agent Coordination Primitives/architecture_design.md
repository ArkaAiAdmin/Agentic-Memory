Five sibling submodules expose a flat public API re-exported from `coordination/__init__.py`, each owning one concern over shared SQLite tables in the active agent's `memory.db`:
- `locking.py` — exclusive file locks backed by `file_locks` with an auto-migrated `lock_version` column; `acquire_lock_fenced` returns a `FencingLock` (monotonic version) so callers must call `verify_lock_fenced` before writing to prevent TOCTOU races. Uses `BEGIN IMMEDIATE` transactions.
- `messaging.py` — `agent_messages` queue supporting point-to-point (`to_agent`) and broadcast (`to_agent='*'`); in-process `_subscriptions` dict gives push-style delivery via `check_messages`; undelivered messages older than a cutoff are moved to `dead_letter_messages` by `process_dead_letters`.
- `project_state.py` — simple `project_state` key-value store keyed by `(project_id, key)` with JSON values and `updated_by`/`updated_at` metadata; helpers like `get_active_files` read `file:*` keys.
- `durability.py` — `agent_heartbeats` + `coordination_audit` tables plus maintenance routines (`run_durability_maintenance`, `cleanup_stale_agents`, `release_stale_locks`, `abandon_stale_tasks`, `get_safety_report`).
- `hooks.py` — fail-safe integration surface consumed by save/search/cron pipelines; every function accepts an optional `conn` (tests) or creates its own via `_make_conn()` (production), reads `MEMORY_DB_PATH` / `MEMORY_AGENT_ID` env vars, and wraps all DB calls in try/except that log and return safe defaults. Locking is accessed through late-import wrappers (`_fenced`, `_verify`, `_renew`) to avoid circular imports.

Dependency direction: `hooks` → `locking`/`messaging`/`durability`/`project_state`; `durability.run_durability_maintenance` lazily imports `messaging.process_dead_letters`. Cross-agent writes (e.g. `_send_import_feedback`) reach into peer agents' DBs via `infra.infrastructure.resolve_active_memory_dir` + `memory_sharing._resolve_peer_db_path`.
