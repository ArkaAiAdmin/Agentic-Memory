Three cooperating sub-packages form the in-process memory core:
- `search/` owns the retrieval/reranking pipeline (`orchestrator.py`, `phases/*`, `ltr/*`) plus indexers (`colbert_index.py`, `splade_index.py`, `chunk_index.py`). It consumes `coordination` for fenced locks, per-project key-value state, and inter-agent messaging, but never imports `crdt` directly.
- `crdt/` implements the conflict-free replication layer (`crdt_merge.py`, `crdt_field.py`) that persists notes as LWW-Element-Set fields; it is imported by higher-level sync/saga code rather than by the search pipeline itself.
- `coordination/` provides shared SQLite-backed primitives (`locking.py`, `messaging.py`, `project_state.py`, `durability.py`, `hooks.py`) that both the search pipeline and external agents use to serialize writes and exchange events.
The top-level `agentic_memory` package (outside this scope) wires them together: the save pipeline calls `crdt.crdt_merge.crdt_save` / `crdt_field_save`, then triggers `coordination.hooks` so the search indexer can rebuild its ColBERT/SPLADE indices after durable state changes. Coordination's fenced locks are the single serialization point between concurrent agents running the same search pipeline.
