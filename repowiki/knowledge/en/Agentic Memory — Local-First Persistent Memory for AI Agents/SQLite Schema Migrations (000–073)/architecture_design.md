Flat, numbered migration directory consumed by a Python migration runner; each feature is split into an up file (`NNN_<name>.sql`) and a down file (`NNN_<name>.down.sql`). Migration 000 defines the base `memories`, `kg_entities`, `kg_edges`, `kg_facts` tables plus the FTS5 virtual table and its triggers. A single-row `schema_version` table (migration 001) tracks applied version and is re-bumped by marker-only migrations (e.g. 053, 073) when code paths change without DDL. The schema evolves through distinct phases: vector embeddings and indexes (002–004), KG constraints and temporal facts (006, 018), field-level CRDTs with separate `_append` tables for write safety (013, 021, 065, 073), multi-tenant isolation via `tenant_id` columns and backfills (042–056), RBAC principals/roles/policies/acl_overrides (043–048, 054), outbox/saga/coordination/distributed-lock tables (031–032, 068–072), and search/reranker structures (057–059). Down migrations are paired but not all implement full reversals — many are empty or placeholder, reflecting an append-only / additive-evolution strategy where data fixes are preferred over destructive drops.
