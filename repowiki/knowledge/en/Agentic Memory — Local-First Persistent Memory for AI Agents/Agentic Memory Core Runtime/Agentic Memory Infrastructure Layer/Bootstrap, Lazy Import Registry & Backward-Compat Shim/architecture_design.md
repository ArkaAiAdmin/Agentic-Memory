Three independent, side-effect-driven helpers consumed by entry points:
- `_bootstrap_path.py` runs first (imported with `# noqa: E402`) to resolve `INSTALL_ROOT` from `MEMORY_INSTALL_ROOT` or the package's parent directory — falling back to `~/.config/agentic-memory` if `memory_config.py` is missing — and inserts it at `sys.path[0]` so top-level packages like `memory_common`, `save_pipeline`, `search.orchestrator`, etc. are importable.
- `_lazy_imports.py` holds a single `_LAZY_IMPORTS` dict mapping public names to `(module, attr)` tuples and exposes them via a module-level `__getattr__`, so callers write `from infra._lazy_imports import save_memory` while the real `save_pipeline`/`infra.memory_common`/etc. modules are only imported on first attribute access, breaking circular dependencies such as `memory_common → config → memory_common`. A runtime `_add_lazy_import` helper lets tests or extensions register new mappings.
- `_shim.py` provides an `install_shim(name, real_module)` helper plus a `_ShimModule(types.ModuleType)` subclass that forwards `__getattr__`/`__setattr__`/`__delattr__`/`__dir__` to a stored `_real` module; shim files at old package locations call `install_shim(__name__, _real)` inside their `if __name__ in sys.modules:` guard to transparently re-export the relocated implementation without changing callers.

Dependency direction is one-way: shim and lazy-import code depend only on stdlib (`sys`, `types`, `importlib`, `pathlib`); they do not import any application package, keeping them safe to run before the rest of the tree is bootstrapped.
