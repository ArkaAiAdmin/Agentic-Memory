Two parallel subsystems live side-by-side under `infra/`:

- Caches: `cache.py` holds a thread-safe `OrderedDict` LRU for FTS5 search results with per-note reverse-index invalidation (`register_cache_note_ids` / `invalidate_cache_for_note`) and lazy-resolved TTL flags via `make_lazy_getattr`. `arc_cache.py` persists ARC ghost-list state and stats to SQLite through `sqlite_write_queue`, exposing `record_eviction`/`record_hit`/`compute_eviction_pressure` as the eviction-pressure signal consumed by `tier_migration.py`. `policy_hash_cache.py` is a thin file-backed JSON cache over `.peer_policy_cache.json` using `atomic_write`.
- Locking: `dist_lock.py` defines the `Lock` Protocol plus three implementations (`FileLock` via `fcntl.flock`, `InMemoryLock`, `NullLock`) selected by `get_lock(backend=...)`. `file_lock.py` wraps that protocol with retry/backoff semantics and a `strict` mode that raises `FileLockError` on write paths. `lock_manager.py` provides a second, pluggable abstraction (`LockManager` subclass hierarchy: `FlockLockManager`, deprecated `SQLiteLockManager`, `RedisLockManager`, `PostgresLockManager`) registered globally via `get_lock_manager()` and selected by `MEMORY_LOCK_ENGINE`; `file_lock._try_flock` delegates to it so both lock surfaces share one backend.

Dependency direction: caches depend only on stdlib + `infra.db_write_queue`/`infra.memory_common`; locking modules are self-contained and imported by higher-level saga/save/search code. The two subsystems do not import each other.
