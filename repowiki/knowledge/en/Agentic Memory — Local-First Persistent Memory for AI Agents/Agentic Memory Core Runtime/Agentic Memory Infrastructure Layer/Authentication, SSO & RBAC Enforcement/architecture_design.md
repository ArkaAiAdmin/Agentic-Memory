Four cooperating modules form the auth stack:
- `authlib_sso.py` is the identity provider layer: `KeyManager` persists RSA JWKs in `idem_token_key`, `SsoSession` drives OIDC authorize/token exchanges and SAML metadata fetches via `IdPMetadataCache`, while `sign_token`/`verify_token` handle service-side JWTs and `verify_oidc_id_token`/`parse_saml_response` validate external tokens. All XML parsing goes through `_safe_parse` (defusedxml or DOCTYPE-stripped fallback) and SAML signature verification requires the optional `pyxmlsec`+`lxml` stack.
- `authorizer.py` is the enforcement choke point: `resolve_principal` maps bearer tokens to `Principal` objects (static `[api.principals]` TOML mapping, then DB lookup by `principal_identities.external_sub`, then `MEMORY_AGENT_ID` local fallback), and `mcp_authorize` normalizes verb actions/resources to canonical RBAC vocabulary before delegating to `rbac.check_permission`, adding tenant-scoped cross-tenant admin checks. `Authorizer` is a thin OO wrapper; audit decisions are recorded via `log_authorization_decision` into `memory_audit_log`.
- `rbac.py` holds the policy engine: `check_permission` evaluates ACL overrides first, then role→policy joins (with wildcard resource/action matching and optional `effect='deny'` exclusion), defaulting to deny. Default roles/policies are seeded idempotently by `seed_default_roles`.
- `gdpr.py` implements cascading subject deletion across memories/KG/embeddings/audit tables in dependency-safe order, anonymizing `memory_audit_log` rows instead of deleting them for SOC2/HIPAA retention, and producing a signed `DeletionCertificate` persisted in `gdpr_requests`.

Dependency direction: `authorizer` → `rbac`; `authlib_sso` writes principals that `authorizer` reads back — there is no reverse import. All three layers share the same SQLite schema (`principals`, `role_bindings`, `policies`, `acl_overrides`, `gdpr_requests`) and connect via `infra.db.open_db`.
