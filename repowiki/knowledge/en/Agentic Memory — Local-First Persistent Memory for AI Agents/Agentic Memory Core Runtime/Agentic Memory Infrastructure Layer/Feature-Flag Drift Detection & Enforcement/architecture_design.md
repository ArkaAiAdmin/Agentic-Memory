Six cooperating modules form a layered pipeline: `config_drift.py` owns the pure data layer — flag registry (`FlagSpec`), four-source decomposition (`_decompose` → `FlagSource`), verdict rules (`_verdicts`), snapshot build/persist/diff (`build_drift_report`, `persist_drift_report`, `diff_reports`), and the mutable `_FLAG_TIERS` table plus its TOML-driven override loader. `config_drift_policy.py` sits on top as the enforcement policy resolver: it picks a scope-based default (`_SCOPE_DEFAULTS` for production/staging/test/development), overlays `[drift]` from memory.toml, optionally subscribes to `infra.toml_watch` hot-reload, and exposes `run_startup_enforcement()` / `enforce()` which raise `DriftEnforcementError` or log warnings depending on mode. `config_drift_runtime.py` is an in-process-only rolling-window counter (`record_drift`, `should_escalate`) that promotes WARN→SOFT_BLOCK→HARD_FAIL when hits exceed `progression_max_hits`. `config_drift_escape.py` parses `MEMORY_ESCAPE_HATCH` into a bounded `EscapeHatch` that temporarily downgrades enforcement to warn for a scoped tier. `config_drift_audit.py` provides append-only JSONL persistence with rotation, shared by all other modules. `config_drift_tier_patch.py` applies `[drift_tiers]` overrides against the live `_FLAG_TIERS`, restoring hardcoded defaults when overrides are removed. Dependency direction is one-way: audit ← escape ← runtime ← policy ← core; tier_patch bridges back into core's mutable tier table. All I/O is isolated behind thin wrappers so `build_drift_report` itself is pure.
