Three-file leaf module:
- `llm_extraction.py` is the real implementation. It defines a thread-safe singleton `LLMExtractor` that lazily loads a small instruction-tuned model (`Qwen/Qwen2.5-1.5B-Instruct`, default) via `transformers.AutoModelForCausalLM` + `AutoTokenizer` on MPS or CPU, then prompts it with `_EXTRACTION_PROMPT` to emit JSON `{facts:[...],entities:[...]}` which is parsed and normalized (predicate mapping in `_PREDICATE_NORMALIZE`, article stripping, confidence clamping). A daemon idle-unload monitor frees GPU memory after a configurable timeout. Two parallel code paths exist: the legacy path (`extract_facts_via_llm`, `extract_entities_via_llm`) talks directly to `LLMExtractor`; the newer S3 path (`*_v2` functions, `is_llm_extraction_available_via_provider`, `_extract_via_provider`) delegates to `fact.llm_providers.get_provider()` supporting Ollama/llama.cpp/HF backends, falling back to the legacy path when no provider is configured. Contradiction scoring (`score_fact_contradiction_via_llm[_v2]`) uses a separate `_CONTRADICTION_PROMPT` returning a float in [0,1]. Hook subprocesses are detected by name and short-circuited so they never load the model.
- `fact_temporal.py` and `adaptive_retention.py` are pure shim layers that re-export `fact.fact_temporal` and `background.adaptive_retention` respectively via `__getattr__`/`__dir__` (plus an `install_shim` call), preserving import paths used by older callers while the real logic lives elsewhere.
