The `fact/` package is a thin re-export shim (`__init__.py`) that flattens symbols from sibling submodules so callers can still import from the legacy `fact_extraction` path. The real logic lives in:
- `fact_schema.py`: idempotent DDL via `ensure_facts_schema(conn)` — creates `kg_facts`, backfills B24/B25/S1 columns plus T1.x v18 temporal columns (`event_time`, `valid_at`, `invalid_at`, `superseded_by`, `supersedes`, `contradiction_score`, `invalidation_reason`, `transaction_time`), FTS5 virtual table `kg_facts_fts` with ai/ad/au sync triggers, and all indexes.
- `fact_temporal.py`: the core temporal engine. Pure helpers `_event_times_match` / `detect_fact_contradiction` sit atop DB-mutating primitives `supersede_fact` / `_mark_fact_superseded` / `invalidate_fact`. `reconcile_fact_supersession` is the hot-path entry point called after each INSERT; it selects candidates by S+P, applies deterministic pre-filtering, optionally augments with an LLM confidence score gated by `MEMORY_TEMPORAL_KG_LLM` + tiered threshold, then calls `propagate_entity_supersession` to cascade stale facts sharing the same subject/object entity. `invalidate_stale_facts` diffs old vs new memory content and expires removed facts. Read-only accessors `_temporal_fact_clause`, `query_facts_at_time`, `query_fact_supersession_chain`, `query_facts_changed_since` provide T4 time-travel semantics over `valid_at`/`invalid_at` (world-time) or `transaction_time` (knowledge-time). All DB mutations wrap their own `BEGIN IMMEDIATE`/`COMMIT`/`ROLLBACK` when not already inside a transaction, and best-effort side effects (belief_assertions, entailment_chains, audit log) are caught and logged rather than raised.
- `llm_extraction.py` is a one-line re-export shim pointing at the repo-root `llm_extraction.py`; actual LLM scoring lives there and is imported lazily inside `reconcile_fact_supersession` only when enabled.
- Supporting modules `fact_clean.py`, `fact_extract.py`, `fact_search.py`, `consolidate_facts.py`, `llm_providers.py` provide extraction pipelines, search, and consolidation; they depend on this temporal layer indirectly through `index_facts_for_memory` which calls `reconcile_fact_supersession` and `invalidate_stale_facts` after upserts.
Dependency direction: `fact_temporal` → `infra.db.AnyConnection` (type-only), `config.get_config` (lazy import), `llm_extraction.score_fact_contradiction_via_llm` (lazy import); no reverse imports into extraction/search modules.
