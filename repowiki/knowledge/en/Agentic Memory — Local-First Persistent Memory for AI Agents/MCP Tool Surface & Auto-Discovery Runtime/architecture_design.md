The top-level `mcp_tools.py` is the orchestrator: it scans the directory for `mcp_*.py`, imports each one (skipping itself and `mcp_instance`) to trigger their `@mcp.tool()` registration side effects, then flattens all exported `memory_*` symbols plus a small `_extra_exports` set into a single `__all__`. A module-level `__getattr__` provides lazy fallback resolution for circular-import cases where a domain module tries to import another before Phase 2 completes. All domain modules share `mcp_common.py`, which bootstraps the canonical `_bootstrap_path`, re-exports infrastructure helpers (`open_db`, `with_audit`, `with_memory_connection`, `resolve_active_memory_dir`, etc.), and exposes shared utilities like `_run_subprocess_output` and `recompile_skills_catalog`. Domain modules are grouped by concern (memory/session/profile, knowledge-graph/search, maintenance/admin, quality/safety/audit, sharing/collab/multi-modal) but communicate only through this flat registry — there is no cross-module import graph among them beyond `mcp_common`.
