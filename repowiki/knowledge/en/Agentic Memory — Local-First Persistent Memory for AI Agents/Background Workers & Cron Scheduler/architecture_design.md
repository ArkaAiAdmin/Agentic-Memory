Two cooperating subsystems share one contract: `background/background_queue.py` exposes an in-process `enqueue_task()` API backed by the `memory.db` SQLite table; `cron/scheduler.py` (the cron runtime) is the sole producer, calling this API from ~40 declarative job definitions, while `background/daemon.py` + `background/fleet_worker.py` are the long-lived consumers pulling jobs off the same table. All cron entry points (`cron_*.py`) and the daemon import the same `jobs.py` / `enqueue_task.py` registry rather than talking to each other directly, so isolation is enforced by the queue table schema and row-level locking. The daemon also owns auto-save, retention coordination, corpus budget guards, and circuit-breaker state that the cron jobs read via the same SQLite store, making the database the cross-subsystem boundary.
