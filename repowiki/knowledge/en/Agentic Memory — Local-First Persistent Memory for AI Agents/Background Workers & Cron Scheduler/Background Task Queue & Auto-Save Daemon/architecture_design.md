Two cooperating subsystems share a single SQLite `memory.db`:

- **Task queue** (`background_queue.py`) defines the `task_queue` table (pending/processing/completed/failed with priority, attempts, max_attempts) and exposes `enqueue_task` / `dequeue_task` / `complete_task` / `fail_task`. Backpressure is built in via `RejectPolicy.REJECT_OLD|REJECT_NEW|BLOCK` and an optional cap. Dequeue uses `BEGIN IMMEDIATE` to serialize workers; nested transactions are handled by falling back to SAVEPOINT when the caller already owns a transaction.
- **Worker loop** (`background_worker.py`) polls the queue in three modes — `--once`, `--drain`, or continuous `--interval=N` — dispatching each task through a `HANDLERS` registry keyed by `task_type`. Handlers call into `kg/`, `save/`, `reasoning/`, `belief/` subpackages and also shell out to sibling scripts (`rebuild_vec_index.py`, cron scripts) via `subprocess.run`. A per-task SIGALRM watchdog (configurable via `MEMORY_WORKER_TASK_TIMEOUT_S`) prevents runaway tasks from blocking the queue. A separate reconciler thread runs vec-index drift checks and periodic WAL checkpoints.
- **Auto-save daemon** (`daemon.py` + `inbox.py`) is a separate long-running process that tails `.auto_save_inbox.jsonl`, batches entries, and persists them via `_tool_complete_inner`. It uses flock-based mutual exclusion, PID files, and a global manifest for multi-project coordination, and implements at-least-once delivery by renaming the inbox to a `.pending.{pid}` file before processing and re-processing orphaned pending files on restart.
- **Circuit breaker** (`circuit_breaker.py`) tracks failure windows in-process and persists open/close transitions to `memory_audit_log`; a sentinel file coordinates with the TS plugin so it won't spawn new auto-save subprocesses while the circuit is open. Shared-memory mirroring (`infra.shared_memory_state`) lets CLI hooks read state without importing Python.
- **Adaptive retention** (`adaptive_retention.py`, `retention_coordinator.py`, `corpus_budget_guard.py`) records user access events in `user_access_log` and periodically adjusts note decay half-lives based on access frequency, gated by `MEMORY_ADAPTIVE_RETENTION=1`.
- **Fleet entry points** (`fleet_entry.py`, `fleet_worker.py`) provide fork-safe sharded worker processes that import only the reconciliation function they need, avoiding module-level daemon-thread initialization in child processes.

Dependency direction: this package depends outward on `infra.*` (db pool, rate limiter, shared memory, file locks, config), `kg/`, `save/`, `reasoning/`, `belief/`, and sibling top-level scripts; nothing outside imports internals beyond the public `background.background_queue` API and the `run_daemon` entry point.
