The repository is a single `agentic-memory` pip package (`pyproject.toml`) whose root `.py` modules form the runtime glue between the child subsystems: `infra/` (shared DB, config, migrations, metrics, file locks), `save/` + `recall/` (core save/recall pipeline), `search/` (14-phase hybrid search), `knowledge_graph/`, `kg/`, `fact/`, `background/` + `cron/` (daemon + scheduler), `mcp_*.py` (tool registry auto-discovered by `mcp_tools`), `agentic_memory/` (public SDK surface re-exported by `sdk_package`), `cli.py` (legacy CLI shim consumed by `cli_entrypoints`), and `cloud_sync/` (separate SaaS plane). All services are orchestrated at process-start via the `SERVICE` env var in `docker-compose.yml`, which selects one of three long-lived processes — `mcp`, `sync`, or `cron` — all sharing a single `/data` volume so they read/write the same SQLite WAL. Cross-process writes are serialized through flock-based saga primitives in `infra/`. Optional feature gates (`embeddings`, `reranker`, `ltr`, `ner`, `dashboard`, `langchain`, `crewai`) are declared as extras in `[project.optional-dependencies]` and gated at import time via `_lazy_imports.py`. The top-level `Makefile` exposes unified targets (`test`, `lint`, `typecheck`, `update-docs`, `update-schema`, `update-mcp-tools`, `precommit`) that drive pytest over `eval/`, ruff/mypy over the config-drift surface, and AST-driven doc generators under `scripts/`.
