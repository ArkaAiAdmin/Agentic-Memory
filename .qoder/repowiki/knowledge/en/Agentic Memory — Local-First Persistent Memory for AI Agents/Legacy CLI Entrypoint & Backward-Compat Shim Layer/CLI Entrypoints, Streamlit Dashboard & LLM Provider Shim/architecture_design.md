Three sibling scripts form the public surface of `agentic-memory`:

- `cli.py` is the single process dispatcher. Each command (`server_main`, `search_main`, `rebuild_main`, `backfill_main`, `consolidate_main`, `integrity_main`, `tier_main`, `compact_main`, `bootstrap_main`, `worker_main`, `sync_main`, `init_main`, `doctor_main`, `status_main`, `version_main`, `install_mcp_main`, `dashboard_main`) is a top-level function invoked by the package's console-script entry point. Long-running or complex commands are delegated via `_run()` which spawns a child Python process pointing at a sibling script under this directory (or `cron/`). The `server_main` path is special: it auto-initialises the memory directory tree on first run, then imports `mcp_instance` / `memory_mcp` and runs the MCP server loop.
- `dashboard.py` is a Streamlit application entry point. It sets page config, resolves the SQLite DB path, wires an `ApiClient` against the REST API (resolved from `MEMORY_API_BASE` or `[api]` config), performs a login gate using a persisted token or interactive JWT flow, and renders one tab per `render_*` function imported from `dashboard.tab_*` modules.
- `llm_providers.py` is a pure compatibility shim: it dynamically forwards all attribute access to `fact.llm_providers` so older code importing the old location keeps working.

Dependency direction is outward-only: these three files import from `infra.*`, `config`, `background.*`, `memory_integrity`, `mcp_instance`, and the local `dashboard/` package; nothing in those packages imports back into them. Process boundaries are enforced through `subprocess.Popen`/`subprocess.run` rather than threading — the dashboard and background workers are separate processes managed by PID files.
