Flat collection of independent entry-point scripts plus a pytest-driven test suite. Three layers coexist:
- Test harness: `conftest.py` + `_fixtures.py` provide session-scoped env setup (OpenMP/OMP thread limits, MEMORY_* flags), a `temp_db_path` fixture that bootstraps a fresh SQLite DB via `infra.db_migrations.run_schema_setup`, RBAC fixtures (`closed_auth_env`, `ClosedClient`), and autouse fixtures that clear the connection pool, auto-save circuit breaker, and lazy config cache between tests.
- Benchmarks: top-level runners (`real_memory_eval.py`, `locomo_eval.py`, `adversarial_memory_eval.py`, `retrieval_benchmark.py`, `embedding_benchmark.py`, `perf_envelope.py`) each own their CLI, seed a temp DB through `_fixtures.bootstrap_temp_db_clean`, populate multi-index backends (chunk FTS, vector embeddings, ColBERT, SPLADE, KG, facts) via `populate_eval_memory_indexes*`, run queries against `search.orchestrator.search_memories`, and write JSON reports to `eval/results/`.
- Sub-suite packages: `longmemeval_s/` (LongMemEval_S with multiple strategy runners and metrics), `beam/` (BEAM synthetic long-context benchmark with scale configs), `benchmarks/` (micro-benchmarks for save/search throughput).
- Orchestration: `run_full_suite.py` is the single CI entry — it spawns each `test_*.py` in its own subprocess under `KMP_DUPLICATE_LIB_OK=TRUE`, sets `MEMORY_DB_PATH` to a per-test temp file, runs pytest with `-m 'not slow' --junit-xml`, parses JUnit XML for counts, and aggregates results into `results/full_suite_results.txt`.
Dependency direction is one-way: every runner imports from `infra/*`, `search.*`, `knowledge_graph`, `fact`, `save.indexers`, and `memory_mcp`; nothing in `infra` imports back into `eval/`.
