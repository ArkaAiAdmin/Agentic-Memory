Single-package Streamlit app under `dashboard/` with a clear separation between shared infrastructure and per-tab renderers:
- `__init__.py` is the shared foundation: defines the global CSS theme (`CSS`, `DARK`), the tab registry (`TABS`), DB resolution via `infra.infrastructure.resolve_active_memory_dir`, read-only SQLite helpers (`get_conn`, `query`, `try_count`, `_table_status`) decorated with `@st.cache_resource` / `@st.cache_data`, plus the health-check subsystem (`_run_health_checks`, `_compute_health_score`).
- `api_client.py` provides an `ApiClient` wrapping `infra/api_server.py` REST endpoints (`/api/v1/*`) over `requests.Session`; every method falls back to a READ-ONLY local SQLite connection only when `DASHBOARD_ALLOW_LOCAL_FALLBACK=1`, and re-raises 401/403 as `_AuthError` so auth failures are never silently downgraded.
- `sidebar.py` owns the left rail: agent/deployment selector (OpenCode vs MIMOCODE or cloud deployments from `infra_cloud.store.CloudStateStore`), live metrics, quick actions, logout, and keyboard shortcuts; it wires `st.session_state.api_client` into the active `ApiClient`.
- `login.py` renders a token→JWT cookie exchange page gated by `requires_login()` (skipped when `MEMORY_API_TOKEN` env var is set).
- `tab_dashboard.py`, `tab_memories.py`, `tab_knowledge.py`, `tab_operations.py`, `tab_audit.py`, `tab_billing.py`, `tab_compliance.py`, `tab_coordination.py`, `tab_quality.py`, `tab_settings.py` each expose a single `render_*` function consumed by the top-level Streamlit entry point (outside this module) which builds the tab layout.
- `tabs.py` is a legacy compatibility shim kept for tests; the active code path uses the individual `tab_*.py` modules.
Dependency direction: tabs → `dashboard` + `dashboard.api_client` + `sidebar`; `sidebar` → `api_client` + `dashboard`; `api_client` → `infra.api_server` (HTTP) and optionally `dashboard` (fallback); no cross-tab imports.
