Two sibling packages form the execution core of the search system:

- `search/phases/` — one module per phase, each exposing a single public function consumed by the orchestrator. Phase responsibilities are declared in `__init__.py`'s docstring: retrieval (`retrieve.py`, FTS5 BM25 + embedding fallback + SPLADE), hybrid fusion via RRF (`fusion.py`, merges FTS/vector/chunk/SPLADE with adaptive overfetch and a thread-pooled `_hybrid_fusion`), envelope filtering (`envelope.py`), KG centrality/multi-hop traversal (`kg_traversal.py`), contradiction supersession (`contradiction_engine.py`), session-aware clustering (`session.py`), post-processing/safety gates (`postprocess.py`), deterministic answer solvers (`math_aggregator.py`, `temporal_delta_solver.py`, `attribute_extractor.py`), and telemetry (`telemetry.py`). Shared DB helpers live in `_db_utils.py`. Phases are pure readers or best-effort writers; failures are swallowed so no phase is a hard precondition.
- `search/ltr/` — a late-stage rerank that takes over ordering after all CE / late-interaction work. `scorer.py` lazily loads a LightGBM model from `models/ltr/model.txt`, calls `features.extract_ltr_features` to build a fixed-width feature vector, writes `r[6]` (final_score) exactly once (the "RANK-FIRST LOCK"), then sorts and truncates. `features.py` defines the ~25-feature schema and batch-prefetches KG edge/entity counts via `prefetch_kg_features`. `session_ctx.py` builds `prior_clicked_ids` / `prior_returned_ids` from recent CTR feedback for dwell features.

Dependency direction is strictly inward: phases depend on `infra.db.AnyConnection`, `search.config.get_search_config`, `search.scoring._reciprocal_rank_fusion`, and optional lazy imports (`infra._lazy_imports.get_embedding_search`, `infra.splade_encoder.encode_sparse`, `adaptive_retention.record_access`). The LTR package depends only on `search.ltr.features` and the external LightGBM runtime. There is no cross-import between `phases/` and `ltr/`; the orchestrator wires them together.
