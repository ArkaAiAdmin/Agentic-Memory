Two cooperating modules form a dual-path merge layer:

- `crdt_field.py` is the v13 true-CRDT implementation. It stores per-field state in a `memory_field_crdt` table keyed by `(memory_id, field_name)` with columns `(value, version_vector, logical_clock, last_writer_agent, is_deleted)`. The replicated fields are fixed to `content`, `tags`, `category` (`REPLICATED_FIELDS`). Merge logic is pure: `merge_field_updates()` groups updates by `(memory_id, field_name)`, sorts them canonically by `(logical_clock, serialised_vv, agent_id)`, then folds via `_merge_two()` which applies vector-clock dominance followed by an LWW tiebreaker on `(clock desc, agent asc)`. Persistence goes through `apply_field_updates_to_db()`, which reads the existing row, runs `_merge_two`, and writes only when the incoming update wins — including a special un-tombstone path that lets a live write beat a stale tombstone. Projection helpers `project_sql_to_crdt()` and `project_crdt_to_sql()` keep the `memories` row and the CRDT table in sync; `backfill_from_memories()` seeds the CRDT table from legacy notes.

- `crdt_merge.py` is the thin entry point `crdt_save()` / `crdt_sync_all()`. On each call it probes whether `memory_field_crdt` exists; if so it delegates to `crdt_field.crdt_field_save` and then calls `project_crdt_to_sql` plus enqueues background tasks (`embedding_index`, `kg_and_fact_index`, `semantic_backlinks`). If the table is absent, it falls back to the legacy note-level LWW+version-vector path implemented inline here, supporting three whole-note policies: `supersede` (default), `replace` (archives old rows as `__v_<clock>`), and `coexist` (creates `__conflict_<agent>` copies). Both paths wrap their DB work in a `Saga` with explicit undo closures restoring pre-state rows.

Dependency direction: `crdt_merge.py` imports `crdt_field` lazily at runtime (inside `crdt_save`) to avoid import cycles and to gate the field-level path behind a schema probe. Both modules depend on `infra._lazy_imports.open_db`, `save_pipeline.upsert_row`, and `infra.memory_common.safe_atomic_write`; neither imports the other at module load time.
