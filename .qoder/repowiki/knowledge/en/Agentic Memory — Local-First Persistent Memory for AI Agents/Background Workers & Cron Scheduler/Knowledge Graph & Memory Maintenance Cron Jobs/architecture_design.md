Each file is an independent `__main__`-style CLI wrapper around a reusable implementation in another package (e.g. `cron_kg_backfill.py` → `backfill_all.py`, `cron_concept_drift.py` → `search.orchestrator._record_drift_event`, `cron_skill_extraction.py` → `skill_extractor.*`). The wrappers share a common shape: parse args, resolve `MEMORY_DB_PATH` or `resolve_active_memory_dir() / 'memory.db'`, acquire a filesystem lock via `_flock.acquire_lock_or_exit('<job_name>')`, set up logging through `infra.log.setup_logging`, then call the real logic and print a single summary line on stdout for crontab consumption. Long-running jobs (`cron_kg_backfill`, `cron_kg_analytics`) wrap their work in `background.cron_model_lock.cron_model_lock(job_id)` so only one instance of that job runs at a time across processes. Cross-agent sync jobs (`cron_sync`, `cron_crdt_sync`) additionally bootstrap the local CRDT server via `infra.sync_server_daemon` when configured and iterate over `cfg.sync_peers`. Dependency direction is strictly outward: these scripts import from `infra.*`, `save.*`, `search.*`, `kg.*`, `skill_extractor`, and `background.*`; nothing inside this module is imported by application code — they are leaf entry points only.
