Five cooperating leaf modules form the KG consistency pipeline:
- `contradiction_detector.py` is the scanner: it loads active `memories` rows (tenant-scoped via `tenant_memories`) and runs two detectors — a high-precision phrase/negation matcher (`detect_contradictions`, Phase 1) and an antonym-aware semantic polarity detector using model2vec embeddings (`detect_contradictions_semantic`, Phase 2). Results are emitted as `{source, target, type, confidence, evidence_a, evidence_b}` dicts.
- `contradiction_resolver.py` consumes those pairs and applies one of four actions (`supersede_b_with_a`, `supersede_a_with_b`, `merge`, `keep_both`). Strategy selection is deterministic by timestamp unless `MEMORY_CONTRADICTION_AUTO_RESOLVE_LLM=1`, in which case an LLM provider from `fact.llm_providers` is queried; all actions delegate to `save.pipeline.memory_supersede_db` / `save_memory_auto`.
- `temporal_resolver.py` is a deprecated bridge that reuses the detector to close conflicting notes by setting `valid_to`/`superseded_by` on the `memories` table and optionally invalidating KG edges — retained only for backward compatibility.
- `kg_dedup.py` is the cron entry point (`main()`) that groups `kg_entities` by `(name, entity_type)` for exact dedup and also offers embedding-based candidate generation via `infra._lazy_imports.get_embedding_search()` with cosine-similarity thresholding; both paths funnel into `merge_entities`, which sums mentions, redirects source/target edges (deduplicating existing edges by incrementing weight), and deletes stale rows inside explicit `BEGIN IMMEDIATE` transactions guarded against proxy connections already in a session.
- `kg_crdt.py` implements S2 Causal Graph CRDTs: version-vector helpers (`vv_dominates`, `vv_merge`, …), pure merge functions (`merge_entity_ops` with 2P-Set semantics + LWW per field, `merge_edge_ops` with add-only tombstones), append-only op-log tables (`kg_entity_crdt_append`, `kg_edge_crdt_append`), name-collision resolution via inception fingerprints plus a durable `kg_entity_redirect` loser→winner map, and the `project_crdt_to_entities` pipeline that projects merged state back into `kg_entities`/`kg_edges` while enforcing the no-orphan invariant. The legacy `kg_entity_crdt`/`kg_edge_crdt` tables are kept for readers during deprecation.

Dependency direction is one-way: temporal_resolver → contradiction_detector; resolver → save.pipeline; kg_dedup → infra.db_write_queue + infra._lazy_imports; kg_crdt owns its own schema creation and does not import other kg.* modules.
