Two-file leaf module split by concern: `belief_schema.py` owns the DDL (a single `_BELIEF_SCHEMA_SQL` string with `CREATE TABLE IF NOT EXISTS belief_assertions` plus six indexes) exposed via `ensure_beliefs_schema(conn)`; `belief_lifecycle.py` exposes stateless functions that operate on an injected `AnyConnection` from `infra.db`, keeping this package free of ORM or connection management. The table models a belief layer over `kg_facts`/`memories` where each fact has at most one assertion (`UNIQUE(fact_id)`), storing confidence, epistemic source, certainty tier, rationale, and a JSON `evidence_chain` of fact ids. Status is a closed set `{active, retracted, deprecated, unconfirmed}` enforced in `update_belief_status`. Cascade propagation is handled two ways: `retract_dependent_beliefs` reacts to a superseded fact id, while `handle_evidence_chain_staleness` is a batched background task that scans active assertions whose evidence chains reference facts with `superseded_by IS NOT NULL` and marks them deprecated. All SQL is parameterized with SQLite `?` placeholders; JSON fields are serialized/deserialized via `json.dumps`/`json.loads` inside the function boundary.
