Five cooperating modules form the DB persistence layer:

- `db.py` owns `_ConnectionPool`, a per-path LRU pool keyed by `(path, thread_id)` with depth tracking, inode drift detection (evicts connections when `memory.db` is replaced via `os.replace`), and a background revalidator thread. It exposes `open_db()` as the canonical context manager that either delegates to the write queue (write path) or returns a pooled read conn, and wires in schema setup, saga crash recovery, and a per-connection `tenant_id()` function + `tenant_memories` view.
- `db_migrations.py` is the migration safety-net: every `_migrate_*` helper is idempotent (`CREATE TABLE IF NOT EXISTS`, `ALTER TABLE ADD COLUMN` guarded by `PRAGMA table_info`) and runs inside `run_schema_setup(conn)`, which also calls the numbered SQL runner from `infra.migration_runner`. Both `db.py` and `memory_common.py` import here to break their circular dependency.
- `db_write_queue.py` implements `SQLiteWriteQueue`, a daemon thread backed by `queue.Queue` that serialises all mutating SQL on one real `sqlite3.Connection` per session. Callers get a `ProxyConnection` whose `execute/executemany/commit/rollback/close` are marshalled over two `queue.Queue`s; sessions idle for `MEMORY_WRITE_QUEUE_IDLE_S` then auto-commit/rollback and close. The worker wraps every operation in `db_path_flock(db_path)` so cross-process serialisation is guaranteed even if callers bypass `open_db()`.
- `db_path_flock.py` provides `db_path_flock(path)` — a per-DB-path, per-call, re-entrant flock wrapper around `infra.lock_manager.get_lock_manager()`. Enabled by default unless `MEMORY_DB_FLOCK=0`; used automatically by `open_db()` and explicitly by the write queue worker.
- `write_journal.py` is a separate `journal.db` (CQRS write-ahead log). Each thread caches its own connection in `threading.local()`; `enqueue_write` appends rows without locks (WAL handles concurrency). A reconciliation daemon (outside this module) claims batches via `dequeue_pending_for_worker` using `(id % n_workers) = worker_id` sharding, with retry/dead-letter (`mark_retry`, `mark_dead_letter`) and size pruning (`JOURNAL_MAX_SIZE_BYTES`).

Dependency direction: `db.py` → `db_write_queue` → `db_path_flock` → `infra.lock_manager`; `db.py` lazily imports `db_migrations.run_schema_setup`; `write_journal.py` depends only on stdlib + `save.pipeline.SaveRequest`. No file in this scope imports each other except the documented `db.py ↔ db_migrations.py` lazy link.
