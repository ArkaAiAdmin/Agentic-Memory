Three sibling modules each register read-only MCP tools via `@mcp.tool()` decorated with `@with_audit(...)`, acting as thin presentation/authorization layers over internal packages:
- `mcp_kg.py` exposes `memory_graph_search`, `memory_graph_stats`, `memory_facts_search/list/stats`, `memory_graph_insights`, and `memory_graph_evolution`; it delegates to `knowledge_graph.graph_*_db` and `fact.*_db` helpers, plus `kg.graph_analytics` / `kg.graph_communities` for PageRank, betweenness, and connected components.
- `mcp_kg_traversal.py` adds `memory_graph_shortest_path` and `memory_graph_traverse`, delegating to `kg.kg_traversal.find_shortest_path` / `traverse_graph`.
- `mcp_search.py` provides `memory_search` (hybrid FTS5 + semantic rerank via `search_pipeline.search_memories`), `memory_semantic_search` (subprocess call to `GLOBAL_SCRIPTS_DIR/embedding_search.py`), `memory_recall_context`, and `memory_session_start` (which also pulls spaced-repetition review counts from `review_schedule`).

All three files share a common authorization shim (`_check_authorization` in `mcp_kg.py`) that lazily imports `infra.authorizer.mcp_authorize` and fails open when RBAC is unavailable; every tool resolves its SQLite path through `_resolve_memory_dir() / "memory.db"` and opens it via `infra.db.open_db(..., write=False)` or `row_factory=None`. DB schema references are hard-coded (`kg_entities`, `kg_edges`, `graph_snapshots`, `review_schedule`), so these tools depend on the persistence layer's table layout rather than an ORM. Optional features (spaced repetition, self-directed tiers, embedding model) are imported lazily inside functions so their absence does not break cold-start.
