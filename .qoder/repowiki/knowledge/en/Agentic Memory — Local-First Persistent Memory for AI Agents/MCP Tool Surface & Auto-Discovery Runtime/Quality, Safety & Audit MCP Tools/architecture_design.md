Three sibling modules each register one or more `@mcp.tool()` handlers on the shared `mcp` instance from `mcp_instance`, with every handler wrapped by `@with_audit(...)` so calls are persisted to the `memory_audit_log` table. Cross-cutting concerns (active directory resolution via `_resolve_memory_dir`, error formatting via `_err(ErrorCode.*)`, logging) come from `mcp_common`; DB access goes through `infra.db.open_db` / `infra._lazy_imports.open_db` using a read-only URI (`file:...?mode=ro`) when only querying to avoid flock contention with the auto-save daemon.

- `mcp_quality.py`: opt-in quality gates gated by `MEMORY_QUALITY_GATES=1`; delegates filtering/stats to the lazy-imported `quality_gates` module against `search_memories` results.
- `mcp_safety.py`: three tools — `memory_scan_injection` (delegates to `infra._lazy_imports.scan_for_injection`), `memory_strip_provenance` (`memory_injection.strip_provenance`), and `memory_check_contradictions` (pre-save phrase-level check via `memory_contradiction_save.check_contradictions_on_save`).
- `mcp_audit.py`: extracted from `mcp_maintenance.py`; provides health/audit reporting (`memory_audit`), audit-log query (`memory_audit_query`), circuit-breaker event history (`memory_circuit_breaker_status`), index/data integrity (`memory_check_integrity` → `memory_integrity.check_index_integrity`), temporal KG queries (`memory_temporal_contradictions`, `memory_temporal_query` via `fact.fact_temporal`), and workflow compliance scoring (`memory_compliance_check`).

Dependency direction is outward-only: these files depend on `mcp_common`, `mcp_instance`, and domain packages (`infra`, `memory_*`, `fact.*`, `quality_gates`, `search_pipeline`); nothing inside this scope imports back into them.
