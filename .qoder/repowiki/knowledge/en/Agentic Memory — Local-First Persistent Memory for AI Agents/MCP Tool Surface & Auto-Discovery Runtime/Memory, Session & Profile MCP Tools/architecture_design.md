Three thin MCP-tool modules that register functions via the `@mcp.tool()` decorator from `mcp_instance.mcp`, each wrapping a domain concern:
- `mcp_memory.py` — write/read/delete/restore/trash/purge/supersede/reinforce tools. Write paths go through `save_pipeline.save_memory` (or `save_memory_journal` when `config.write_journal` is enabled), with optional coordination locks (`coordination.hooks.acquire_save_lock`) and RBAC checks (`infra.authorizer.mcp_authorize`). Read-only helpers call into `memory_delete`, `background.auto_save`, and `infra.cache`.
- `mcp_session.py` — thread-context/list/resolve tools backed by `session_manager.SessionManager`; session_id defaults to `.current_session.json` in the active workspace.
- `mcp_profile.py` — opt-in access-recording and profile query against the `user_profile` module, gated by `MEMORY_USER_PROFILE=1`.

All three modules bootstrap path resolution via `from mcp_common import _bootstrap_path` (side-effect import) and return errors through `_err(ErrorCode.X, ...)` wrapped by the `@with_audit(name)` decorator, which records an audit entry before every tool invocation. Cross-cutting concerns (error codes, logger, JSON helpers, DB flock, cache invalidation) live in `mcp_common`; persistence logic lives outside this scope in `save_pipeline`, `memory_delete`, `session_manager`, `background.auto_save`, and `user_profile`.
